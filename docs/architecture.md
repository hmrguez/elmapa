# Project architecture

Elmapa is a Bevy 0.19.1 application. Editable documents, variation seeds and brush chronology remain authoritative; entities and GPU assets are disposable views. GPUI and its vendor fork have been removed.

## Domain and editing

`document` owns validated, versioned `.elmapa` JSON, copy-on-write stroke collections, and editable labels. Optional per-layer `labels` arrays extend version 1 compatibly; missing arrays deserialize empty. Labels share the document identifier namespace and enforce text, coordinate, and typography limits (2048 labels per atlas). `editor` owns mutations, layer selection, undo and redo. `storage` provides atomic external saves; `library` owns local atlas snapshots, camera metadata, preferences and rebuildable preview caches. The independent library also powers headless SVG export. No rendering framework leaks into these interfaces.

`app::state::Studio` is a Bevy resource containing the current editing session and presentation state. An atlas switch constructs a new editor; returning home and reopening the active atlas preserves its history. Undo stays within a session. Brush release commits exactly one operation. Toolbar actions finish gestures; Escape cancels. Hidden layers reject painting. Pointer coordinates remain unbounded world coordinates within document validation limits.

`editor` exposes `add_label`, `update_label`, `delete_label`, and rotated `label_at` hit testing. `app::lettering` retains the text-tool selection, reusable style, field drafts, and drag previews. A draft never mutates the authoritative document; valid name drafts and drags render through a temporary document clone until committed. Each field / drag is one undo checkpoint. Native input methods and macOS pasteboard / hidden menu accelerators feed this same edit state. Document switches reset text selection and drafts.

## Schedules and bounded work

The Update schedule orders keyboard and deterministic replay input before the ordinary pointer dispatcher, I/O completion, scene publication, rendering synchronization, camera changes and UI updates. Replay pointer events enter the same ordered `WindowEvent` stream and panel hit testing as native input. Startup creates the render target and cameras, renderer resources and embedded UI assets in order.

Terrain generation runs on `AsyncComputeTaskPool`. One task owns `SceneCache`; subsequent input coalesces into the latest desired state instead of queueing work per pointer event. A revision epoch rejects results after document replacement, undo, cancellation or release. During a gesture, already prepared intermediate snapshots may publish while later points wait. `generation::bounded` retains the existing deterministic geometry/work limits and explicit errors. The document remains available if generation fails.

File dialogs, loading, saving, export, library checkpointing and preferences run on `IoTaskPool`. There is one active operation and one latest pending request. Home, atlas switches and quit wait for a durable local checkpoint. Save completion never clears newer dirty edits. Native macOS menu actions and hidden Cocoa key equivalents enter this same path; the visible application menu stays unchanged. Export writes to a unique temporary file and atomically renames only after successful generation and synchronization. Escape cancels an in-flight export.

## Retained GPU canvas

Each nonforest material batch is tessellated once with Lyon on the scene worker. Its immutable `Arc<Vec<Shape>>` identity maps to a Bevy mesh asset and entity. Mesh positions remain in world coordinates; pan and pointer-anchored zoom change an orthographic camera. They do not transform or upload terrain vertices on the CPU. Removed entities release their asset handles; Bevy retires the GPU assets.

Land and water use sparse, 384-world-unit tiles on a fixed 12-unit sampling grid. Each tile evaluates neighboring samples before clipping the finished fill, shore ink and wash to its own bounds. Live strokes update only tiles reached by new segments or their shoreline effects. The scene retains unchanged batches by identity. The canvas swaps replacements after the render world prepares their mesh buffers and materials. SVG and shelf previews consume the same tile geometry.

Forest specimens adapt the original SVG canopies to a modest oblique view with short trunks and flattened ground washes. Seeds, scattering and collision placement stay stable; instance size is reduced by 20% and tilt is restrained. Within each layer, rivers draw before mountains and trees. Each peak’s two flanks stay together and sort by the shared base, interleaved with trees sorted by trunk position. At equal depth the peak draws over the tree. The shared scene draws trails after the last visible river and before the first visible mountain or tree, including across layers. When a river is on a higher layer than a peak or tree, the affected tree and mountain batches move together to preserve their depth order. The canvas, replay, thumbnails, and SVG use this shared order. Ten specimens share a single atlas image. Cropping preserves the original specimen pixels and transformed pivot, with transparent filtering padding. Bevy automatically batches the trees on one shared strip mesh and atlas material. Each mesh instance carries its specimen index and opacity. Per-variant projected resolution uses the original 32–2048 power-of-two tiers and hysteresis. One coalesced atlas task runs on the compute pool; the previous tier remains visible while the next is prepared. Four atlas columns keep the largest texture within an 8192-pixel dimension. The largest tier occupies 192 MiB; old/new assets can overlap during replacement and GPU retirement.

Trees are ECS entities keyed by stable `TreeId`. Only trees with a `Growing` component update their transforms for animation. Settled trees use retained transforms. `ForestAnimation` retains the original 240 ms growth, spatial stagger and overshoot. A vertex shader uses Bevy’s global clock and each trunk’s world position to bend the crown in gentle waves. The roots stay anchored, and Reduced Motion disables sway through the shared material. Saves, shelf previews, and SVG export use final geometry. Bevy handles frustum culling and mesh batching. Z encodes the ordered scene batches, including interleaved material/layer order.

Text is shaped by usvg / Rustybuzz using the installed preset fonts and system fallback coverage. Glyph contours become Lyon triangles with counters preserved; native canvas, bounds, hit testing, shelf previews, and self-contained SVG export consume the same geometry. A bounded shaping cache and retained per-label batches avoid reshaping settled names. Each layer's labels follow its terrain and inherit layer opacity; higher layers cover them. `Dropping` components animate only newly placed / duplicated label meshes: a 300 ms, eight-unit descent with a subtle scale settle. Reduced motion finishes immediately; undo, reopening and exports never replay placement animation. No glyph font files are redistributed.

Parchment fibres are world anchored. Their snapped visible bounds update on a bounded task; a previous mesh remains visible during generation. At extreme overview scales, the existing fibre work limit omits only paper detail, preserving terrain.

## Presentation and UI

The UI uses Bevy nodes, text, image masks, gradients and box shadows. The original logical-pixel measurements, Avenir Next/Baskerville faces, line heights, palette, radii, panel widths and spacing are retained. Original MIT-licensed icons are embedded. Font hinting is enabled. Static chrome is rebuilt only when its state changes; camera percentages, cursor feedback, hover colors, menu motion and book transitions update independently. Shelf/layer scroll offsets survive rebuilds. UI hit regions use computed layout and inherited clipping, including empty panel backgrounds, so controls cannot paint through to the map.

GPUI blended authored colors and masks into an unorm, gamma-space framebuffer. Default Bevy linear blending makes partially covered glyphs and icon edges appear paler. `app::presentation` renders authored gamma-space colors to an unorm target and uses one final sRGB decoding pass for the native window. This preserves the original compositing convention while all rendering and asset lifetime management belong to Bevy. The render target and UI scale follow physical window size/device scale; logical panel sizes remain fixed. No backdrop blur is introduced: the original glass appearance consists of translucency, gradients, borders and layered shadows.

The shelf retains at most sixteen preview image handles. Preview generation runs separately from interaction. A cached preview expands during the 1.15 s book transition and the original hinged cover peels away. Reduced motion bypasses growth/hover/menu/book animations. macOS system fonts are read from their installed files, not redistributed.

## Measurement

`ELMAPA_TRACE` opts into bounded in-memory events and allocator/RSS observation. Normal runs do not install timing observers. On macOS, a process-local `CAMetalLayer.nextDrawable` observer adds a presented callback without changing submitted drawing commands. Actual positive drawable timestamps determine displayed FPS. Bevy schedule/frame-loop durations are recorded under distinct names and are never relabeled as GPU execution or display time.

See the [runtime protocol](performance-runtime.md) for validation. Native font rasterizers can produce different glyph coverage even with identical font faces; visual comparisons are required alongside measurements.

## Landmarks

Optional per-layer `landmarks` arrays extend version 1 compatibly. `Landmark` stores a shared document ID, stable kind, world ground anchor and size. Missing arrays deserialize empty; validation caps landmarks at 2,048 per document. Editor mutations share layer/history rules with labels. `app::landmarks` owns placement, selection and temporary move previews; each completed drag is one checkpoint. Select can route a canvas hit to either the lettering or landmark adapter. Hidden and transparent layers reject landmark edits.

`assets/landmarks/packs/*/manifest.json` defines stable pack/item IDs, display metadata, optional icons, SVG files, dimensions/anchors and ordered assembly sequences for named SVG groups. `build.rs` discovers bundled packs without per-asset code. `scene::landmark_packs` validates bundled and installed packs once at startup, tessellates artwork atomically per pack and caches geometry/bounds. Installed packs live under the library’s `landmark-packs/` folder. Invalid packs are reported in Settings. `scene::landmarks` produces world-space per-part batches from this shared catalog. Landmark IDs are strings (`pack:item`); legacy unqualified IDs map to `elmapa.basic`. Missing packs retain their IDs with the bundled pin as display fallback. Disabled pack IDs are persisted in shelf preferences and affect only the picker, leaving document rendering and editing intact. One enabled pack yields a flat item ring, several yield pack branches and nested item rings; missing pack icons use the name’s first letter. Shelf preview cache keys include the catalog fingerprint so changed packs refresh their artwork. `SceneCache` retains unchanged landmark batches independently of terrain. Landmarks follow roads/rivers and precede text within each layer. Cold scene building, hit testing, content bounds, thumbnails and SVG use the same final vector geometry.

Only explicit arrivals receive native assembly clocks. `app::landmark_render` updates transforms and material opacity for temporary `Assembling` components, then removes them at the final pose. A separate transient shader draws the ground-ink splash and retires its material after 700 ms. Reduced Motion, undo/redo and atlas replacement clear or bypass arrival motion. No animation clock, shader geometry or partial pose enters a document/export. The existing reusable glass orbit renders specimen previews and editing actions around the selected landmark.

The JSON/SVG pack revision was verified in isolated native apps with the bundled basic pack, an installed `astral:observatory` fixture (different SVG dimensions and no pack icon), and a malformed pack. Native checks covered settings persistence across quit/relaunch, the one-pack flat orbit, E/first-letter pack icons, nested selection and Escape, all-packs-disabled feedback, retained placed artwork, and corrected icon contrast in dark mode. The existing landmark replay also exercised assembly, move/undo/redo, visibility/opacity, both themes, reduced motion, save/reopen and SVG export; its saved/local documents matched and preserved the custom pack ID. The final release build was inspected separately. All required checks passed: 139 Rust tests (one manual benchmark ignored), icon exports, Python trace tests, formatting, Clippy with warnings denied, and demo SVG export.

Native validation uses [the landmark replay](landmark-native-replay.json) in an isolated macOS app/library. It places all four specimens, captures a live town frame and completed artwork, exercises a Select-tool move/undo, saves and exports, checks visibility and opacity, switches between Holo and Paper and enables reduced motion, reopens the file and returns to the shelf. The replay's pointer events use the ordinary Bevy input dispatcher. Direct native toolbar/orbit clicks and duplicate/delete/undo shortcuts were also exercised; CUA's native drag operation returned `noWindowsAvailable`, so the displayed replay supplies drag validation. The real atlas library is not touched. To repeat, build with `--release`, prepare a fresh bundle with `scripts/prepare-native-test-app.py --replay docs/landmark-native-replay.json` and an isolated `/private/tmp` library, launch it and press **p**. Captures use `/tmp/elmapa-landmark-*.png`; save/export artifacts live in the isolated library.

Landmark depth is authored in the ordered SVG/registry groups and remains independent of placement delay. Each overlapping town building and harbor structure has its own retained batch and ground pivot; a late-arriving rear house therefore stays behind nearer roofs instead of sharing a foreground group's transform. Opaque faces occlude rear foundations and crane braces in both native/export geometry. Regression tests sample those exact overlap locations; the castle's geometric tier test checks matching pairs around an increasingly tall center.

The depth/castle revision first reproduced two incorrect topmost ink samples against the shared tessellated geometry; changing only painter order made both pass. The completed revision passes 133 Rust tests (one manual benchmark remains ignored), icon generation, Python trace tests, formatting, Clippy with warnings denied and demo SVG export. An isolated release/Metal replay captured live town/harbor assembly and final artwork, exercised move/undo/redo, layer visibility/opacity, both themes, reduced motion and save/reopen/export. Its saved document exactly matches the previous artwork fixture; move-undo and redo canvas pixels match.
